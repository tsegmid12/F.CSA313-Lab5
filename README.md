## 1. Төслийн танилцуулга

Энэхүү лабораторийн ажлаар Node.js ашиглан боловсруулсан Course
Registration REST API системийг Postman болон Newman хэрэгслээр
тестэлсэн. API нь оюутан үүсгэх, хичээл үүсгэх, хичээлийн мэдээлэл авах,
оюутныг хичээлд бүртгэх болон бүртгэлийн мэдээлэл авах үндсэн
үйлдлүүдийг дэмжинэ.

Postman collection ашиглан амжилттай хүсэлт, алдаатай хүсэлт, давхар
алдааны нөхцөл болон сервертэй холбогдох боломжгүй үеийн ажиллагааг
шалгасан.

### 4.1 Тестэд ашигласан жишээ өгөгдөл

  -----------------------------------------------------------------------
  Үзүүлэлт                Сонголт                 Төлөөлөх утга
  ----------------------- ----------------------- -----------------------
  Оюутны төлөв            Идэвхтэй                `B231234567`,
                                                  `status: active`

  Оюутны төлөв            Идэвхгүй                `B231234568`,
                                                  `status: inactive`

  Оюутны төлөв            Байхгүй                 `B999999999`

  Үзсэн хичээл            Бүгдийг үзсэн           `["CS201", "CS202"]`

  Үзсэн хичээл            Огт үзээгүй             `[]`

  Үзсэн хичээл            Заримыг үзсэн           `["CS201"]`

  Хичээл                  Байгаа                  `CS313`

  Хичээл                  Байхгүй                 `CS999`

  Урьдчилсан нөхцөл       Бүгд хангагдсан         `["CS201", "CS202"]`

  Урьдчилсан нөхцөл       Огт хангагдаагүй        `[]`

  Урьдчилсан нөхцөл       Зарим хангагдсан        Хичээлд `CS201`,
                                                  `CS202` шаардлагатай
                                                  боловч оюутан зөвхөн
                                                  `CS201` үзсэн
  -----------------------------------------------------------------------

Амжилттай бүртгэлийн тест нь хариуны `result` утга `OK` эсэх болон
`registrationID` талбар байгаа эсэхийг шалгана. `registrationID`-г
тогтмол утгатай гэж үзэж шалгахгүй.

### 4.2 Давхар алдааны шалгалт

Double Error тестээр идэвхгүй оюутныг байхгүй `CS999` хичээлд бүртгүүлэх
хүсэлт илгээнэ. Энэ үед нэг хүсэлтэд хоёр алдааны нөхцөл зэрэг байна.

API нь оюутны мэдээллийг эхэлж шалгадаг тул хүлээгдэж буй хариу нь
`ERROR_INACTIVE_STUDENT` байна. Энэ тест нь API-ийн validation шалгах
дарааллыг баталгаажуулна.

## 5. Тестийн цуглуулга

Үндсэн тестийн цуглуулга нь `lab05-collection.json` файлд байрлана.
Үндсэн collection нь дараах 9 бүлэгтэй:

1.  Амжилттай бүртгэл (Happy Path)
2.  Идэвхгүй оюутан (Inactive Student)
3.  Олдоогүй хичээл (Course Not Found)
4.  Урьдчилсан нөхцөл хангаагүй (Missing Prerequisite)
5.  CourseID байхгүй (Missing CourseID)
6.  StudentID байхгүй (Missing StudentID)
7.  Олдоогүй оюутан (Student Not Found)
8.  Буруу JSON өгөгдөл (Invalid JSON)
9.  Давхар алдаа (Double Error)

Шаардлагатай тохиолдлуудад эхлээд оюутан болон хичээлийн мэдээллийг
үүсгэх тохиргооны хүсэлт илгээж, дараа нь үндсэн API хүсэлт болон
хариуны шалгалтыг гүйцэтгэнэ.

`lab05-collection-fail.json` нь үндсэн collection-той ижил хүсэлтүүдийг
ашиглах боловч зарим assertion-ийн хүлээгдэж буй утгыг зориудаар буруу
тохируулж, тестийн систем алдааг илрүүлж байгааг шалгана.

## 6. Newman тестийн үр дүн

### 6.1 PASS тест

Ажиллуулах команд:

``` powershell
newman run .\lab05-collection.json
```

  Үзүүлэлт                  Үр дүн
  ----------------------- --------
  Гүйцэтгэсэн хүсэлт            21
  Алдаатай хүсэлт                0
  Гүйцэтгэсэн assertion         41
  Амжилтгүй assertion            0
  Newman exit code               0

**Үр дүн:** PASS. Нийт 41 assertion амжилттай шалгагдсан.

Лог файл: `results/newman-pass.txt`

### 6.2 FAIL тест

Ажиллуулах команд:

``` powershell
newman run .\lab05-collection-fail.json
```

FAIL collection-д зарим assertion-ийн хүлээгдэж буй үр дүнг зориудаар
буруу болгож, бодит API хариу болон хүлээгдэж буй утгын зөрүүг Newman
илрүүлж байгаа эсэхийг шалгана.

  Үзүүлэлт                  Үр дүн
  ----------------------- --------
  Гүйцэтгэсэн хүсэлт            21
  Алдаатай хүсэлт                0
  Гүйцэтгэсэн assertion         41
  Амжилтгүй assertion            8
  Newman exit code               1

**Үр дүн:** FAIL тест хүлээгдэж буй байдлаар ажилласан. Зориудаар буруу
болгосон 8 assertion амжилтгүй болсон.

Лог файл: `results/newman-fail.txt`

### 6.3 DOWN тест

Энэ тестийг гүйцэтгэхийн өмнө API серверийг зогсооно.

Ажиллуулах команд:

``` powershell
newman run .\lab05-collection.json
```

  Үзүүлэлт                                 Үр дүн
  ------------------------------ ----------------
  Гүйцэтгэхээр оролдсон хүсэлт                 21
  Холболтын алдаатай хүсэлт                    21
  Assertion                                    41
  Амжилтгүй assertion                          41
  Холболтын алдаа                  `ECONNREFUSED`
  Newman exit code                              1

**Үр дүн:** API сервер ажиллахгүй үед Newman холболтын алдааг илрүүлсэн.

Лог файл: `results/newman-down.txt`

> Тайлбар: PASS, FAIL болон DOWN хэсгийн тоонууд нь collection-ийн
> одоогийн хувилбараар Newman ажиллуулсны дараах бодит логтой таарч
> байгаа эсэхийг шалгаж шинэчилнэ.

## 7. Алдааны шинжилгээ

Энэхүү лабораторийн ажлын хүрээнд дараах төрлийн алдааг шалгасан.

-   **Assertion алдаа:** API хүсэлтэд хариу өгсөн боловч бодит хариу нь
    хүлээгдэж буй үр дүнтэй таарахгүй байхыг хэлнэ. Үүнийг FAIL
    collection-д хүлээгдэж буй утгуудыг зориудаар буруу болгож
    харуулсан.
-   **Холболтын алдаа:** API сервер ажиллахгүй эсвэл холболт тогтоох
    боломжгүй үед үүснэ. Үүнийг DOWN тестийн `ECONNREFUSED` алдаагаар
    харуулсан.
-   **Давхар алдааны нөхцөл:** Нэг хүсэлтэд хэд хэдэн алдааны нөхцөл
    зэрэг үүсэхэд API аль шалгалтыг эхэлж гүйцэтгэж, ямар алдааны хариу
    буцааж байгааг шалгасан.

Assertion алдаа нь бодит болон хүлээгдэж буй үр дүнгийн зөрүүг
илэрхийлдэг бол холболтын алдаа нь API серверт хүсэлт хүрч чадаагүйг
илэрхийлнэ.

## 8. Дүгнэлт

Энэхүү лабораторийн ажлаар REST API тестлэх болон Newman ашиглан тестийг
автоматжуулах арга барилыг судалж хэрэгжүүллээ. Course Registration
API-ийн ажиллагааг шалгах үндсэн болон сөрөг тестийн тохиолдлуудыг
боловсруулсан. Happy Path тестээр хүчинтэй оюутан хүчинтэй хичээлд
амжилттай бүртгүүлж байгааг баталгаажуулсан. Сөрөг тестүүдээр идэвхгүй
оюутан, байхгүй хичээл, хангагдаагүй урьдчилсан нөхцөл, дутуу ID болон
буруу JSON өгөгдлийг шалгасан. Мөн Double Error тестээр нэг хүсэлтэд
хоёр алдааны нөхцөл зэрэг үүсэхэд API-ийн шалгах дарааллыг
баталгаажуулсан.

PASS тест нь бүх assertion амжилттай болсон эсэхийг, FAIL тест нь
зориудаар буруу тохируулсан assertion-ийг илрүүлж байгаа эсэхийг, DOWN
тест нь сервертэй холбогдох боломжгүй үед Newman алдааг мэдээлж байгаа
эсэхийг шалгасан. Ийнхүү API-ийн хэвийн ажиллагаа, алдааны нөхцөл болон
Newman автоматжуулалтын үндсэн ажиллагааг туршиж үзлээ.
